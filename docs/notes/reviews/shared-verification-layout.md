# Shared verification layout review

Reviewed 2026-09-23: the integrator's working diff against `931e47f`,
read-only from an independent worktree. Scope: moving `corpus/` and
`oracle/` beneath `tests/`, their callers/configuration, and discovery gates.

## Findings

- **Broken moved documentation links, fixed during review.** Twelve links
  in the ACL, priority, stacks, verify-error, parser-error and stateful
  READMEs still used `../../docs/`, which resolves under `tests/` after the
  move. They now use `../../../docs/`. Sibling corpus links remain valid;
  the oracle READMEs correctly account for their new depths.
- **Guard the real discovery lists, fixed during review.** The initial new
  minimum-count guard checks the actual corpus directory has ten programs
  and fifteen vectors, but by itself cannot catch a typo in an oracle
  suite's independent glob. Recommended strengthening: compare discovered
  program/vector lists from the actual corpus, SpecTec and BMv2 suites,
  including strict known-divergence IDs. This is a future-regression
  weakness, not a mismatch in the inspected migration.
- Minor stale command comments in `flake.nix` still named the old
  `oracle/build.sh` path when first inspected; report to integrator for
  correction. Historical design/review paths are not migration defects.

## Independently checked

  using the review environment and read-only access to the integrator's
  source. Actual discovery is **10 programs and 15 vectors** in the corpus,
  **15** in SpecTec and **15** in BMv2. All three vector-ID sets are equal.
  `register_bounds/bounds.stf` is still present in the BMv2 known-divergence
  set; strict xfail marking code is unchanged. The integrator strengthened
  the guard to compare these actual discovery lists, and directly invoking
  that revised guard independently passed.
- Compared the old corpus tree with the relocated tree: application Python
  sources, `.txtpb` goldens and STF vectors are byte-identical. Differences
  are README path repairs and existing generated bytecode directories.
  Printer golden files have no diff.
- Existing test assertions are unchanged except path/import updates and
  the added layout/discovery guard. No assertion removal, new skip, xfail
  weakening or oracle-output normalization was found.
- CI's Docker context, oracle build command, pin extraction and cache-key
  paths now point to `tests/oracle`. Upstream image/source/tool pins remain
  unchanged. Docker still copies its driver relative to the same context.
- The direct-script Python search roots use the correct new parent depths:
  `tests/oracle/run.py` uses `parents[2]`, and its BMv2 sibling uses
  `parents[3]`. The explicit `tests` package resolves the relocated imports.
- Pyright now includes the oracle Python code because all of `tests/` is
  included. The Linux-only `fcntl.F_SETPIPE_SZ` access changed to equivalent
  `getattr(fcntl, "F_SETPIPE_SZ")`; there is no default or swallowed

- `git diff --check` on the inspected main diff succeeds.

No remaining semantic blocker was found. This review did not run the
